# 代码走读手册（Day 1）

目标不是背代码，而是能做到两件事：

1. 在白纸上画出数据流；
2. 用自己的话解释每个工具“为什么存在”。

## 第 0 步：先跑起来

```powershell
python analyze.py --offline
```

观察终端里的三行 `[tool]`，这就是 Agent 的完整工作过程。

## 第 1 步：记住一条主线

```text
comments.xlsx
   │
   ▼
read_comments         读取 + 清洗
   │  comments: list[dict]
   ▼
analyze_comments      情感 / 主题 / 风险 / 建议
   │  report: dict
   ▼
save_report           落盘
   │
   ├── report.json
   └── report.md
```

面试时先讲这条线，再展开细节。

## 第 2 步：五个检查点

### 检查点 1：Excel 是怎么读进来的？

看 `CommentAgent.read_comments`。

要能回答：

- 表头是怎么识别的？如果列名写成“评价内容”还能读吗？
- 空行和缺失评分怎么处理？
- 为什么读完要 `workbook.close()`？

### 检查点 2：情感分是怎么算的？

看 `POSITIVE_LEXICON`、`NEGATIVE_LEXICON`、`_match_terms`、`_analyze_comment`。

要能回答：

- 为什么负面词表存正数、合并时再取负号？
- “不闷汗”为什么不会被判成负面？
- 为什么最终得分要结合评分，而不是只看关键词？

### 检查点 3：主题是怎么归因的？

看 `_topic_evidence`。

要能回答：

- 为什么先按标点分句，再判断主题？
- 一条评论为什么可能同时命中多个主题？
- “收到货发现线头”里的“收到货”为什么不算物流问题？

### 检查点 4：工具是怎么暴露给大模型的？

看 `TOOLS`。

要能回答：

- 每个工具的名称、参数、描述分别是什么？
- 为什么 `analyze_comments` 不需要把整张表作为参数传进去？
- 工具描述写得好不好，会怎样影响模型行为？

### 检查点 5：Agent 循环在做什么？

看 `_run_llm`。

要能回答：

- `messages` 里为什么要有 `assistant` 的 `tool_calls` 和 `tool` 的结果？
- 模型不调用工具、直接回答时，代码怎么兜底？
- 工具报错时，为什么不让程序直接崩溃？

## 第 3 步：读完必须能回答的 4 个问题

1. 如果 Excel 多一列“商品ID”，要改哪些地方？
2. 如果要把“物流包装”拆成“物流速度”和“包装质量”，要改哪里？
3. 如果模型返回的工具参数不是合法 JSON，代码会怎么处理？
4. 如果没有 API Key，程序靠什么完成同样的流程？

## 第 4 步：动手改三处

每改一处，提交一次 Git：

1. 在 `NEGATIVE_LEXICON` 里加一个你熟悉的差评词，重新运行，观察结果变化；
2. 在 `_analyze_comment` 的返回结果里加一个字段，例如 `content_length`；
3. 把情感判定阈值从 `0.2` 改成 `0.3`，观察哪些评论的标签变了。

> 改完必须能说出：改了什么、为什么改、结果发生了什么变化。
